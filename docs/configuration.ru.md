# Настройка Agenter

Здесь описана конфигурация провайдеров моделей, автоматической маршрутизации, MCP-серверов и навыков. Все пути отсчитываются от корня репозитория. После изменения файлов в `config/` перезапустите API: конфигурация загружается при старте.

## Переменные окружения и первый запуск

Требуется Node.js 24+. Установите зависимости через `npm install`, скопируйте `.env.example` в `.env` и запустите `npm run dev:api` и `npm run dev:web` в разных терминалах. `.env` не коммитьте и не вставляйте ключи в YAML/JSON.

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `PORT` | Порт API | `3000` |
| `DB_PATH` | Файл SQLite с чатами | `./data/agenter.db` |
| `OPENAI_API_KEY` | Ключ для провайдеров с `apiKey: ${OPENAI_API_KEY}` | Не задан |
| `AGENTER_API_TARGET` | Цель прокси `/api` в Vite; задаётся в окружении процесса веб-сервера | `http://localhost:3000` |

API читает `.env` из корня проекта. Отсутствующий ключ у *неосновного* удалённого провайдера не мешает запуску с локальной моделью, но запрос к этому провайдеру не заработает. Для основного провайдера ключ обязателен, если он указан через `${…}`.

## Провайдеры моделей: `config/providers.yaml`

```yaml
defaultProvider: local
providers:
  local:
    type: openai-compatible
    baseUrl: http://localhost:8080/v1
    apiKey: local
    model: my-local-model
  api-smart:
    type: openai-compatible
    baseUrl: https://api.openai.com/v1
    apiKey: ${OPENAI_API_KEY}
    model: example-model-id
```

- `defaultProvider` — ID провайдера из `providers`. Он показывается в интерфейсе как основной.
- `type` сейчас поддерживает только `openai-compatible`. Приложение отправляет потоковый запрос на `baseUrl/chat/completions`; укажите базовый URL с `/v1`, если этого требует сервер.
- `model` должен совпадать с идентификатором, который понимает ваш endpoint. Для некоторых локальных серверов это имя загруженной модели, для других — полный путь. Не копируйте путь из примера, если модель расположена у вас иначе.
- `apiKey` для локального сервера может быть непустой заглушкой; для удалённого используйте ссылку на переменную окружения. Значение `${OPENAI_API_KEY}` подставляется целиком, фрагменты строк не интерполируются.
- Необязательный `contextWindow` задаёт размер контекста; без него адаптер использует `8192`.

В текущем репозитории объявлены `local`, `api-smart` и `api-fast`. Настройте их модели и endpoint под свой сервер. Перед отправкой с инструментами убедитесь, что выбранная модель поддерживает **Chat Completions с function/tool calling**: адаптер пока не использует Responses API.

Проверить загруженные ID и модели можно через `GET http://localhost:3000/api/providers` или в списке «Модель» в чате. API-ключи в этом ответе не выводятся.

## Автоматический выбор: `config/routing.yaml`

Режим `Auto` использует правило из файла `routing.yaml`. Все пять секций — `simple`, `coding`, `reasoning`, `research`, `vision` — обязательны; в каждой укажите существующий ID провайдера:

```yaml
routes:
  simple: { provider: local }
  coding: { provider: local }
  reasoning: { provider: local }
  research: { provider: local }
  vision: { provider: local }
```

Текущий классификатор проверяет признаки по порядку: изображение → `vision`, выбранный навык → `coding`, доступные в этом запросе инструменты → `reasoning`, иначе → `simple`. Секция `research` необходима для формата конфигурации, но сейчас автоматически не выбирается. Включение MCP-сервера с функциями переводит обычный запрос в маршрут `reasoning`; если удалённый API-ключ не задан, назначьте этому маршруту `local` либо вручную выберите локальную модель. Изменения маршрутов требуют перезапуска API.

## MCP: `config/mcp.json`

Файл должен быть строгим JSON без комментариев и завершающих запятых. Поддерживаются два транспорта:

```json
{
  "mcpServers": {
    "local-files": {
      "command": "node",
      "args": ["/path/to/server.js"],
      "env": { "TOKEN": "${MCP_TOKEN}" }
    },
    "remote-search": {
      "transport": "sse",
      "url": "http://127.0.0.1:8001/servers/ddg-search/sse"
    }
  }
}
```

Для `stdio` поле `transport` можно опустить; `command` обязателен, `args` и `env` необязательны. В `args` и `env` допускаются ссылки на переменные окружения целым значением. Для SSE укажите только `transport: "sse"` и абсолютный HTTP(S)-адрес `url`. В URL не помещайте логины, пароли и токены. Ваш `mcp_proxy` должен быть доступен **с машины, где запущен API**: адрес `127.0.0.1` внутри контейнера означал бы сам контейнер, а не хост.

В `config/mcp.json` уже внесены шесть предоставленных адресов прокси: `ddg-search`, `gitlab`, `postgresql-mcp`, `chrome-devtools`, `youtube-transcript` и `playwright`. Если сервер вам не нужен, удалите его запись и перезапустите API. SSE здесь — совместимость со старым HTTP+SSE транспортом MCP; для новых серверов в будущем предпочтителен Streamable HTTP ([документация MCP SDK](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/docs/clients/connect.md)).

При запуске API подключается к каждому серверу отдельно и читает каталог его инструментов. В `GET http://localhost:3000/api/mcp` доступны статусы `ready`/`error` и метаданные инструментов; команда запуска, переменные окружения и ключи не возвращаются. В интерфейсе это панель «Инструменты». Имена инструментов получают префикс `<ID-сервера>__`.

Все MCP-серверы в чате **выключены по умолчанию**, даже если их статус `ready`. Откройте панель «Инструменты» и включите нужные серверы переключателями. Их функции станут доступны модели со следующего сообщения. Выбор действует в текущей открытой странице и не сохраняется после перезагрузки; при недоступности сервера он сбрасывается. В одном запросе передаются только функции включённых серверов. Уже запущенный запрос переключение не изменяет. Локальные инструменты, если они зарегистрированы, управляются отдельно и этим переключателем не отключаются.

**Безопасность и размер каталога.** Включение MCP-сервера даёт модели доступ ко всем обнаруженным функциям этого сервера: они регистрируются как `safe` и могут быть вызваны через общий ToolRegistry. Особенно внимательно проверяйте права GitLab, PostgreSQL и браузерных серверов. Отдельного выбора функций внутри сервера пока нет. При проверке 24 сентября 2026 года эти шесть серверов предоставили 201 инструмент. Включение их всех может ухудшить выбор инструмента, увеличить запрос и оказаться несовместимым с ограничениями конкретной модели/API; [руководство OpenAI по function calling](https://developers.openai.com/api/docs/guides/function-calling) советует держать первоначальный набор небольшим. Для практической работы включайте только нужные серверы.

## Навыки: `skills/`

Навык — папка `skills/<id>/SKILL.md` с YAML-заголовком и инструкциями:

```markdown
---
name: Code Review
description: Проверка корректности кода
---

Проверь код и перечисли конкретные замечания.
```

Метаданные загружаются при запуске API, полный текст выбранного навыка — при отправке сообщения. В панели «Инструменты» можно включить один навык переключателем или отключить его повторным нажатием. Кнопка «Добавить» в этом же разделе создаёт новый навык и сразу выбирает его. Если вы добавили файл вручную, перезапустите API. Автоматический выбор навыка сейчас отсутствует. `GET /api/skills` показывает только метаданные.

## Проверка и диагностика

```powershell
Invoke-RestMethod http://localhost:3000/api/providers
Invoke-RestMethod http://localhost:3000/api/skills
Invoke-RestMethod http://localhost:3000/api/mcp
npm run typecheck
npm run lint
npm test
```

Если MCP-сервер имеет статус `error`, проверьте, что прокси запущен, адрес `/sse` доступен API-процессу, а сервер отдаёт корректный каталог инструментов. После устранения причины перезапустите API — автоматического переподключения сейчас нет. Ошибка одного сервера не должна отключать остальные.

Если запрос с инструментами не проходит, проверьте выбранную модель, поддержку tool calling и число подключённых инструментов. Для локального режима также проверьте маршруты `coding`/`reasoning`: они могут указывать на удалённый провайдер без ключа. Не публикуйте в отчётах содержимое `.env`, токены или результаты инструментов с конфиденциальными данными.
