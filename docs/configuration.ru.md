# Настройка Agenter

Настройки доступны через кнопку «Настройки» в истории чатов (на телефоне —
также через шестерёнку в заголовке). Базовая инструкция, модели, Auto и MCP сохраняются одной кнопкой
и применяются к новым запросам без перезапуска. Текущие запросы используют свою
конфигурацию; их MCP-подключения освобождаются после завершения.

## Единый конфиг

Единственный рабочий конфиг — `config/agenter.json`, строгий JSON версии 1.
Если рабочего файла нет, API создаёт его из отслеживаемого в Git шаблона
`config/agenter.example.json`. Шаблон задаёт локальную модель `local-model`
на `http://127.0.0.1:8080/v1`; замените имя модели и лимиты на реальные.
Существующий JSON никогда не заменяется шаблоном, даже если содержит ошибку.
Legacy-файлы providers.yaml, routing.yaml и mcp.json и их загрузчики удалены.
Не удаляйте локальный JSON при обновлении проекта: без него создаётся начальная
конфигурация. Локальный файл и резервная копия исключены из Git;
перенос на другую машину выполняется отдельно. Если нет ни рабочего JSON,
ни шаблона, API завершает запуск с понятной ошибкой.

Сохранение проверяет конфигурацию до записи, пишет временный файл и заменяет
основной атомарно. Предыдущая версия остаётся в `agenter.json.bak`. Если
применение не удалось, рабочий файл восстанавливается. При ручном изменении
файла перезапустите API или откройте настройки и сохраните их для применения.

Пример минимальной локальной конфигурации:

```json
{
  "version": 1,
  "systemPrompt": "You are a helpful assistant.",
  "defaultProvider": "local",
  "providers": {
    "local": {
      "type": "openai-compatible",
      "label": "Локальная модель",
      "baseUrl": "http://localhost:8080/v1",
      "apiKey": "local",
      "model": "my-model",
      "contextWindow": 8192,
      "maxOutputTokens": 1024,
      "timeoutMs": 600000,
      "supportsTools": true,
      "enabled": true
    }
  },
  "routes": {
    "simple": { "provider": "local" },
    "coding": { "provider": "local" },
    "reasoning": { "provider": "local" },
    "research": { "provider": "local" },
    "vision": { "provider": "local" }
  },
  "mcpServers": {}
}
```

## Базовая инструкция

Вкладка «Инструкция» редактирует `systemPrompt` для новых сообщений чата. Он
помещается в начало системного сообщения; затем добавляются инструкции выбранного
навыка и формата ответа. Пустая строка отключает только базовую инструкцию.
Старые файлы `agenter.json` без этого поля продолжают использовать прежнее
значение `You are a helpful assistant.`; при следующем сохранении поле появится
в конфигурации. Изменение применяется после сохранения к новым запросам,
уже выполняющиеся запросы продолжают работу с прежней инструкцией.

## Модели и Auto

Запись модели задаёт endpoint, идентификатор, название для UI, окно контекста,
лимит ответа, таймаут и поддержку инструментов. Поддерживается OpenAI-compatible
Chat Completions; Responses и Anthropic не реализованы. По умолчанию окно — 8192,
лимит ответа — 1024, таймаут — 600000 мс (10 минут). Окно должно соответствовать настройкам
реального сервера, а лимит ответа быть меньше окна. «Проверить endpoint» выполняет
GET `/models`, без генерации и передачи истории. Проверка подтверждает
доступность endpoint, а не поддержку моделью всех возможностей.

Для удалённого endpoint используйте `apiKey: "${OPENAI_API_KEY}"` или другую
переменную. API показывает только ссылку и признак наличия переменной. Для
loopback-сервера допустим пустой ключ, `local`, `ollama` или `lm-studio`.
Значения ключей в конфигурации не допускаются. После изменения `.env`
перезапустите API. Отсутствующий ключ неосновного провайдера не мешает локальному
запуску; его выбор завершится ошибкой провайдера.

Все пять маршрутов обязательны и должны ссылаться на включённые модели.
Классификация: изображение → vision; навык `research` → research; другой навык
→ coding; доступные инструменты → reasoning; иначе simple. Загрузка изображений
в UI пока отсутствует. Отключённую модель сначала уберите из маршрутов и
назначения по умолчанию, затем отключайте или удаляйте.

## MCP

Настройки позволяют создавать и редактировать SSE/stdio-серверы, отключать
подключение, проверять его и выбирать разрешённые функции. «Проверить и получить
инструменты» подключается, читает каталог и закрывает тестовое подключение;
инструменты не выполняются. Для stdio проверка запускает указанную команду
сервера. Сохранение MCP переподключает конфигурацию для следующих запросов.

```json
{
  "transport": "stdio",
  "command": "node",
  "args": ["/path/to/server.js"],
  "env": { "TOKEN": "${MCP_TOKEN}" },
  "enabled": true,
  "allowedTools": ["read_file"]
}
```

Для SSE вместо command/args/env укажите `transport: "sse"` и `url`.
URL использует HTTP(S), без токенов, логина, пароля, query и fragment.
Переменные в args/env интерполируются целым значением `${ENV_NAME}`.
Секретные env-поля требуют ссылку на переменную. Транспорта Streamable HTTP
пока нет. API подключается с таймаутом 10 секунд, вызов MCP — 120 секунд.
Ошибка одного сервера оставляет другие работоспособными.

Новый сервер создаётся с `allowedTools: []`: модель не может вызвать ни одной
функции, пока вы не разрешите нужные. Отсутствие allowedTools означает все
функции; для ограничения явно перечислите разрешённые имена.
Запрещённые инструменты получают `disabled` и не предлагаются модели.
Переключатель подключения в настройках и выбор MCP в чате независимы:
модель получает только разрешённые функции выбранных в чате серверов.

## Навыки и настройки чата

Практические навыки и соответствующие серверы описаны в [каталоге](skills.ru.md).
Инструкции навыка не подключают инструменты автоматически: выберите MCP в чате.
YAML frontmatter в SKILL.md — метаданные документа, а не отдельный конфиг приложения.

Навыки остаются в `skills/<id>/SKILL.md` с YAML frontmatter name/description и
Markdown-инструкциями. Редактор поддерживает предпросмотр с DOMPurify,
редактирование, отключение (`enabled: false`) и удаление. Удаление переименовывает
SKILL.md в SKILL.md.bak, папка и дополнительные ресурсы сохраняются. Для
восстановления верните имя SKILL.md и перезапустите API. ID существующего навыка
сохраняется. Новый навык создаётся через настройки
и автоматически выбирается в чате.

Модель, навык, MCP, глубина истории и черновик сохраняются отдельно для каждого
чата в localStorage браузера. Они восстанавливаются при открытии чата, если
соответствующие возможности доступны. Это настройки конкретного браузера,
они не синхронизируются на другие устройства. История сообщений, запуски и
вызовы инструментов хранятся в SQLite.

В боковой панели «Инструменты» находятся только переключатели навыков и
MCP-сервисов. Можно выбрать один навык и несколько MCP-сервисов. Создание,
редактирование и разрешения функций находятся в настройках.

«Добавить модель» и «Добавить MCP» открывают отдельные формы. Заполните ID и
параметры подключения, нажмите «Добавить в список», затем «Сохранить настройки».
Отмена формы не создаёт запись. Для stdio аргументы и переменные окружения
в форме добавления задаются по одной строке; переменные имеют формат NAME=value.

## Контекст и остановка

Индикатор под вводом показывает оценку занятого окна, резерв ответа и свободное
место. Раскрытие показывает вклад системы, навыка, инструментов, истории,
сообщения и результатов. Оценка использует размер UTF-8 текста и служебный
запас; точное число зависит от токенизатора модели. Сервер проверяет бюджет
перед каждым запросом в tool loop и отказывает при оценочном переполнении.
Оценка может как завышать, так и занижать реальные токены.

Полоса показывает только использованный контекст; резерв ответа отображается
отдельно и вычитается из свободного места. При изменении промпта последняя оценка
остаётся видимой с пометкой «пересчёт…». Ошибка пересчёта помечает её устаревшей.

Можно отправить всю историю, последние 20 сообщений или только новый запрос.
Сохранённая история при этом не удаляется. Автоматического резюмирования нет;
резюме создаётся явной командой `/compact`.
Индикатор контекста относится к очередному запросу, а токены в метаданных
ответа — к суммарному расходу всех обращений модели за запуск. Если провайдер
не возвращает usage, точный расход не отображается.

Команды вводятся вместо обычного сообщения и не отправляются как промпт:

- `/model` открывает выбор модели; `/model local` выбирает провайдера по ID,
  `/model auto` возвращает автоматическую маршрутизацию.
- `/new` создаёт новый чат.
- `/compact` создаёт краткое резюме диалога выбранной моделью, без вызова MCP.
  В Auto используется маршрут по активному навыку или simple. Полная история
  остаётся доступной в чате, а следующие запросы получают резюме и сообщения
  после него. Контрольная точка хранится в SQLite и переживает перезапуск.

Большая история резюмируется частями в пределах окна модели, максимум 64
обращения. Ошибка или остановка сохраняет предыдущий контекст. На коротком
диалоге резюме может занять больше токенов; UI показывает оценку до и после.
«Без прошлых сообщений» исключает также сохранённое резюме из запроса.

«Остановить» и отключение клиента отменяют запрос провайдера и текущий MCP-вызов.
Отмена прекращает ожидание MCP, но не отменяет уже совершённые внешние действия
инструмента. Частичный текст остаётся в текущем UI; успешный ответ не сохраняется
при отмене. Ошибки, длительность, расход и tool activity восстанавливаются при
открытии чата. Частичный текст неуспешного ответа пока не сохраняется в БД.

## Мобильный интерфейс и проверка

На ширине до 800px история и переключатели инструментов открываются боковой панелью,
настройки и редактор навыка — на весь экран. Высота учитывает visualViewport,
safe-area и изменение доступной области при появлении клавиатуры. Проверка в
браузере на 390px не заменяет физическую проверку клавиатуры iOS/Android.
Для подключения телефона нужен адрес компьютера, доступный телефону:
127.0.0.1 на телефоне обозначает сам телефон. Сетевая публикация и авторизация
не входят в эту доработку; интерфейс предназначен для локального использования.

Проверки из корня: `npm run typecheck`, `npm run lint`, `npm test`.
Сборка клиента: `npm run build --workspace=@agenter/web`.
Каталоги: GET `/api/providers`, `/api/skills`, `/api/mcp`.
Настройки: GET/PUT `/api/settings`; проверка: POST `/api/settings/test`.
Навык: GET/PUT/DELETE `/api/skills/:id`; предпросмотр контекста: POST `/api/context`.
Сжатие: POST `/api/chats/:id/compact` с providerId/mode/skillId и поддержкой отмены.

При ошибке MCP исправьте адрес/команду и сохраните настройки для повторного
подключения. Для проверки параметров используйте кнопку проверки в настройках.
Если запрос с инструментами не проходит, проверьте поддержку tool calling,
маршрут Auto и размер контекста. Не публикуйте `.env`, ключи или конфиденциальные
результаты инструментов.
