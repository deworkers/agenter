# Phase 8: Model, Skill, and Tool UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the Vue client for manual/auto provider choice, manual skill choice, MCP/tool visibility, and the shared streaming event protocol.

**Architecture:** API client functions and composables own transport/state; Vue components render them. The client never parses provider-specific payloads. Existing provider-selector work from Phase 2 is retained and brought into this plan's tested contract; skills/tools are additive panels and selectors.

**Tech Stack:** Vue 3, TypeScript, Composition API, `<script setup>`, Vite,
Vitest, existing CSS conventions.

**Spec:** `PROMT.md` §§2, 13, 14, 15, 16, 20, 23, 24 (Phase 8).

## API contracts

- `GET /api/providers` → `{ providers: { id: string; model: string }[]; defaultProviderId: string }`.
- `GET /api/skills` → `{ skills: { id: string; name: string; description: string }[] }`.
- `GET /api/mcp` → server status and tool metadata without secrets.
- `POST /api/chats/:id/messages` accepts `providerId?`, `mode?`, and `skillId?` and emits `AgentEvent` SSE records.

- [ ] **Task 2:** Add composable tests for selected provider, `Auto`, selected skill, loading,

   failure state. Never render unsanitized HTML.
- [ ] **Task 6:** Add provider/model and duration metadata to assistant messages and preserve

- [ ] **Task 7:** Run web tests, root checks, and a manual browser verification against a

## Acceptance criteria

- A user can choose a provider or Auto and choose None or a listed skill.
- Tool calls are visible as collapsible blocks and final text remains usable
  when a tool fails.
- The UI consumes only the shared event protocol and does not leak secrets.
- MVP DoD items 9, 11, 14, 16, and 18 are demonstrably covered.
