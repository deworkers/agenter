# Простая авторизация и отдельная история

Область одобрена запросом пользователя 2026-10-05 и уточнениями: самостоятельная
регистрация по логину и паролю, отдельные чаты и история, общие модели, Skills
и MCP. Работа выполняется по workflow репозитория без Superpowers.

## Реализация

- SQLite для учётных записей и серверных сессий; scrypt с отдельной солью для
  паролей, случайные токены с хранением только SHA-256, срок сессии 7 дней.
- Регистрация, вход, текущая сессия, выход; HttpOnly/SameSite=Strict cookie,
  опциональный Secure для HTTPS, проверка Origin и ограничение попыток входа.
- Все прикладные API требуют сессии. Сервер выбирает хранилище по пользователю
  из сессии; параметры клиента не могут переключать владельца истории.
- Отдельная SQLite-база истории на пользователя. Первый зарегистрированный
  пользователь получает прежнюю DB_PATH без копирования или изменения схемы;
  следующие используют базы в соседней директории `<DB_PATH>.environments`.
- Настройки, каталог навыков и MCP остаются общими, включая редактирование.
  Runtime получает пользовательское хранилище и общий снимок ресурсов.
- Экран входа/регистрации перед загрузкой чата, имя пользователя и выход в
  боковой панели. Состояние приложения сбрасывается при смене сессии;
  браузерные черновики разделяются по ID пользователя.

## Приёмка

Неавторизованные запросы получают 401. Два пользователя не могут читать,
изменять, удалять, сжимать или отправлять сообщения в чужой чат; контекст не
содержит чужую историю. История, учётные записи и сессии сохраняются после
перезапуска. Выход отзывает сессию; просроченные сессии не принимаются.
Пароли и токены не попадают в ответы/логи/репозиторий. Общие ресурсы доступны
обоим пользователям. Невалидные и межсайтовые запросы отклоняются.

Проверки: сфокусированные тесты API и composable/client, root typecheck/lint/test,
production web build, git diff/check/status. Без реальных вызовов модели и MCP.
Системная изоляция файлов, процессов MCP и ключей, роли администратора,
восстановление пароля и подтверждение почты в область не входят.

## Исправление dev-прокси 2026-10-05

Пользователь сообщил 403 при открытии `http://localhost:5173`. Причина:
строковый proxy в Vite неявно включает changeOrigin и заменяет Host на адрес API,
сохраняя браузерный Origin. Proxy переведён в объект с `changeOrigin: false`.
Проверка Origin в API сохраняется. Тест с настоящим Vite-прокси воспроизвёл
подмену Host до исправления; прямой интеграционный тест API теперь отправляет
корректный Origin при регистрации и по-прежнему отклоняет чужой Origin.

Проверено после исправления: root typecheck, 298 тестов, production web build,
lint (0 ошибок; прежние 540 предупреждений) и git diff --check прошли.
Проверка выполнена реальным локальным HTTP/Vite-прокси; рабочие аккаунты
и реальные LLM/MCP-вызовы не использовались. Для применения перезапустить dev:web.
