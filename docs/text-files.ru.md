# Текстовые вложения и файлы ответа

Пользователь запросил эту доработку 2026-09-28. Она расширяет текущий чат,
без новых провайдеров, исполнения файлов и доступа к файловой системе сервера.

## Поведение

- Кнопка «Файл» и перетаскивание добавляют текстовые файлы: txt, md, html, json,
  yaml, xml, csv, исходный код и другие распространённые текстовые расширения.
  Чтение выполняется в браузере. Требуется UTF-8; бинарные данные отклоняются.
- Ctrl+V / вставка на мобильном устройстве вставляет текст длиной до 100
  символов включительно непосредственно в поле ввода. Более длинный текст
  добавляется отдельной карточкой «Из буфера»; промпт остаётся отдельно.
  Принимается только `text/plain`, без картинок и HTML-разметки буфера.
  Карточку можно удалить или развернуть для просмотра текста.
- До 10 вложений: 256 КБ на файл/вставку, суммарно 512 КБ (байты UTF-8).
  Можно отправить только вложения, без промпта. Сервер повторно проверяет
  структуру, размер, имена и текст перед началом SSE.
- Промпт и содержимое документов сохраняются отдельно. В контексте модели
  документы представлены именованными данными внутри пользовательского
  сообщения, а не системными инструкциями. Текущие вложения и документы из
  истории учитываются в оценке контекста и `/compact`.
- Выбор «Ответ: Файл .md / Файл HTML» добавляет инструкцию модели вернуть
  полный документ в блоке `markdown filename=answer.md` / `html filename=answer.html`.
  Для Markdown с внутренними блоками кода модель должна выбрать более длинную
  внешнюю ограду; инструкция содержит пример с `~~~~` снаружи и тройными
  обратными кавычками внутри. Разбор также поддерживает ответ локальной модели
  с одинаковыми внешними и внутренними оградами, если весь документ завершён.
  Контракт выдачи добавляется после инструкций навыка и требует
  ровно один блок с полным содержимым, без описания, плана или выдуманного пути
  к файлу. Навык определяет содержание и дизайн, а файл формируется приложением
  из финального ответа. Модель не должна использовать веб-поиск для записи или
  проверки локального файла. Формат по умолчанию «Текст» сохраняет прежнее поведение.
- HTML должен быть самодостаточным: полный документ с inline CSS/JS,
  без внешних библиотек, шрифтов и сетевых запросов. Инструкции учитывают
  sandbox предпросмотра: код не должен зависеть от cookies, localStorage
  или доступа к родительскому окну.
- Завершённые блоки HTML/Markdown становятся карточками файлов с действиями
  «Скачать» и «Открыть». Имена очищаются от путей и небезопасных символов.
  Успешный ответ целиком также можно скачать как `answer.md`. Во время генерации
  и при ошибке скачивание файлов ответа недоступно, чтобы не выдавать обрывок
  за готовый документ.
- Обычное текстовое описание созданного файла не превращается в HTML-файл.
  Если модель не вернула завершённый файл выбранного формата, интерфейс
  сообщает об этом. Пустой файловый ответ записывается как ошибочный запуск
  с расходом токенов, без пустого успешного сообщения ассистента.
  Для совместимости сырой HTML принимается, если ответ начинается с HTML-разметки;
  Markdown без внешней ограды сохраняется целиком, включая примеры HTML/JS.
  Незакрытая внешняя Markdown-ограда не становится скачиваемым документом.
- HTML открывается в окне просмотра внутри браузера, в sandbox iframe без origin приложения,
  доступа к родительской странице, разрешения форм и навигации верхней вкладки.
  Встроенные CSS/JS разрешены; CSP ограничивает загрузку ресурсов и `fetch`
  текущего документа, поэтому внешние библиотеки в предпросмотре не загружаются.
  Скачиваемый файл содержит исходный документ модели.
  Markdown-просмотр проходит существующую границу DOMPurify и не исполняет JS.

## Хранение и совместимость

Новая таблица `message_documents` хранит JSON с вложениями пользователя и
выбранным форматом ответа. Она создаётся через `CREATE TABLE IF NOT EXISTS`,
не изменяет старые сообщения и удаляется каскадно вместе с их чатом.
Исходный ответ модели остаётся в `messages.content`; карточки восстанавливаются
из него после открытия чата. Черновики документов и формат ответа входят
в существующие настройки чата в localStorage (сохранение зависит от квоты браузера).
Размер JSON-запроса API ограничен 4 МБ для учёта кодирования текстовых данных;
пределы вложений дополнительно применяются к их фактическому содержимому.

## Проверка

Фокус: только текст в буфере, отказ для бинарных/слишком больших файлов,
позднее чтение при смене чата, API-валидация до SSE, учёт файлов в контексте,
сохранение и перезапуск SQLite, удаление метаданных, разбор закрытых оград,
имена файлов, изоляция HTML и восстановление карточек в истории.
Затем root typecheck/lint/test, production web build и браузерная проверка
на desktop и 390px. Физическую клавиатуру мобильного устройства проверить отдельно.

Проверено 2026-09-28: локальная модель получила md/json и текст из буфера,
вернула HTML и затем Markdown; обе карточки восстановились после перезагрузки
клиента и API. HTML просмотрен на desktop и 390px, Markdown — с таблицей и
заголовками. Переход на blob-вкладку заблокирован политикой инструмента, поэтому
просмотр реализован внутри чата через sandbox srcdoc. Событие скачивания
встроенный браузер не подтвердил; путь Blob/download, содержимое UTF-8, имя
и освобождение URL проверены автоматическим тестом. Проверочные вложения
содержали только демонстрационные данные.
Root `npm test`: 247 тестов проходят. `npm run typecheck`, `npm run lint`,
`npm run build --workspace=@agenter/web` и `git diff --check` проходят.
Временная вкладка закрыта, mobile viewport сброшен, тестовый диалог и два
временных файла удалены. Физическая мобильная клавиатура отдельно не проверялась.

Проверено 2026-09-29 после исправления формата ответа: SQLite открыта только
для чтения, исходные чаты и навыки сохранены. Тесты воспроизводят выдачу описания
вместо HTML, пустой успешный файловый ответ и обрезание вложенных Markdown-оград.
257 тестов прошли через `npm run test --workspaces --if-present -- --pool=threads
--maxWorkers=1 --configLoader=native`; стандартный `npm test` блокируется
ограничением запуска процессов `spawn EPERM`. Typecheck и lint проходят.
Сборка использует `npm run build --workspace=@agenter/web -- --configLoader=native`
из-за того же ограничения загрузчика Vite. Прямые запросы локальной модели
с навыком claude-design и вымышленными примерами вернули полноценный HTML
и Markdown с внутренним JavaScript-блоком. Markdown-модель не всегда соблюдает
внешнюю ограду; совместимый разбор сохраняет сырой документ целиком.
Проверочные запросы не создавали записи в SQLite.
